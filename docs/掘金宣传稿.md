# 我开源了一个 AI 讲演助手：导入 PDF，大模型自己写讲稿、用语音逐页讲，听众还能随时打断提问

## 先说痛点

不知道你有没有过这种时刻：

答辩 / 汇报 / 技术分享的前一晚，PPT 早就做完了，但**讲稿还没写**。于是你对着每一页幻灯片，硬憋出几句"本页主要介绍了……"，写完再对着镜子念三遍，第二天上台还是紧张到语速起飞。

反过来，作为听众，你听到一半突然有个疑问，只能憋到 Q&A 环节——那时候你可能已经忘了自己想问什么了。

**OpenPPTSpeaker** 想解决的就是这两件事：让 AI 把稿子写好、把话讲出来，并且允许任何人随时把它打断。

> 一句话定位：**把静态的演示，变成一场可以被听见、也能被追问的讲解。**

## 一、它到底能做什么

一个完整的流程走下来是这样：

1. **导入演示**：拖入一个 PDF（一页自动变成一张幻灯片），或者一组页面图片。
2. **AI 写讲稿**：大模型按页生成逐句讲解词。注意——**每一句都能手改**，AI 只是打底稿。
3. **一键开讲**：讲解词会在开讲前**全部预合成**成音频，字幕跟着真实音频时间轴逐句推进。
4. **聚光定位**：讲到某一句时，页面上对应的区域高亮、其余部分压暗，观众视线不会跑偏。
5. **可打断问答**：听众随时插话，助手立刻停下、回答，然后**从被打断的那一句继续讲**——不是从头，也不是跳过。
6. **手机当麦克风**：同一个 Wi-Fi 下扫个码，手机就变成无线麦克风 + 遥控器（上一页 / 下一页 / 暂停 / 继续 / 结束），**不用装任何 App**。
7. **导出视频**：整场讲解（画面 + 语音 + 字幕）可以直接渲染成 MP4。

> 【配图 3】手机上扫码后的遥控页面截图

几个我觉得挺"产品洁癖"的细节：

- **TTS 合成失败时，宁可静音，也不让 AI 现编内容顶替。** 如果某一页的音频没合成成功，程序会按字数估算时长、静音播放**作者写的原文**，而不是让大模型临时生成一段"大概意思差不多"的话。因为观众听到的内容必须和讲稿一致，这是底线。
- **打断恢复精确到句。** 记录的是"播放到第几句"，恢复时从那一句的音频起点继续，不会出现"接半句话"的尴尬。

## 三、几个值得聊的实现细节

### 1. 为什么是「预合成语音」，而不是边讲边合成

最直觉的做法是：LLM 流式吐字 → 每句话立刻丢给 TTS → 立刻播。

试过就知道，这条路全是坑：

- TTS 首字延迟不稳定，讲解会出现**忽长忽短的停顿**；
- 想同步字幕，只能靠"估算这句话大概念多久"，误差累积后字幕和语音就彻底错位了；
- 一旦某句话合成失败，你没法回头补，只能现场降级。

所以最终架构改成了 **预合成（Pre-synthesis）**：

```
开讲前：把整份讲稿逐句 TTS → 缓存到磁盘（PCM + 每句真实时长）
开讲时：直接播放音频，字幕按【每句音频的真实时长边界】推进
```

代价是开讲前要多等一会儿（UI 会显示"准备音频 x/y"），但换来的是**字幕与语音严格同步**、以及**零实时合成抖动**。

细节上，整段文本是**一次性合成**的（而不是逐句 TTS 拼接），避免逐句合成带来的机械感；字幕再按标点切分成短句，映射到累计时长区间上。

### 2. 字幕同步：两套策略，按场景切换

因为存在两条讲解路径（预合成播报 / LLM 实时生成），字幕的策略也是两套：

- **预合成路径**：字幕由"第几句音频开始播放"的事件驱动。用户听到哪句，字幕就是哪句，**零误差**。
- **LLM 实时路径**（比如打断后的即兴回答）：没有预先知道的时长，就按**字符权重 × 实际播放进度**估算切句。中文按去空格后的字符数分配时间，效果意外地准。

这里有一个很隐蔽的细节：两套策略共用一个状态标记，而预合成路径会把标记置为"按时长边界"，**但不会自动复位**。结果就是——打断提问时，字幕卡在上一段内容不切换，恢复讲解后整体错位。处理方式是在实时播报入口显式关闭该标记，并在注释里写清"为什么必须显式关"。

### 3. 打断策略：短句立即断，长句句末断

"打断"这件事没那么简单。如果听众一开口就硬切，会有两个问题：一是环境音、回声容易造成**误打断**；二是讲解被切得七零八落，听感很碎。

所以做了一个小的决策函数：

```ts
// 已播放超过句末阈值(1600ms) → 让这句自然播完（避免切得太碎）
if (spokenMs >= sentenceThresholdMs) return 'finish-sentence'
// 长句才播了一小段 → 听众是真的急着问，立即停
if (sentMs >= longSentenceMs && spokenMs < sentenceThresholdMs) return 'immediate'
// 其余（播放时间很短、疑似回声）→ 自然播完，不立即打断
return 'finish-sentence'
```

**减少误打断优先**，而不是"反应越快越好"。

打断之后还有一层状态机：进入"倾听中"，只把**像真实问题**的输入交给大模型（带问号、含疑问词、或者足够长），"嗯""好的""你好"这类模糊输入直接当作"继续"，避免 LLM 自由发挥。

### 4. 语音缓存：换音色就自动失效

预合成的音频要落盘缓存，否则每次开讲都重新合成，用户会疯。

缓存 key 是 `sha1(讲稿文本 + TTS 签名)`，其中 TTS 签名包含：**模型 + 引擎 + 音色 + 多音字标注**。这样只要改了文本、或者切换了音色，旧缓存**自动失效**，不会出现"明明换了声音，播放的还是上个音色"的灵异事件。

另外打包版首次运行时，会把安装包里预置的缓存复制到 `userData`——**开箱即用，第一次开讲不用等合成**。

而失败处理是"整页作废"：只要一页里任何一句合成产出为空，就**整页不缓存**并回退。因为部分缓存会导致"缓存句数 ≠ 讲稿句数"，字幕、聚光、打断恢复的索引会全部对不上——这种错位比重新合成痛苦得多。

### 5. 导出 MP4：复用"现场画面"，而不是另画一套

导出视频最怕的是"导出来的效果和现场不一样"。

这里的做法是：**用隐藏的 Chromium 窗口逐句渲染真实画面帧**（和讲解时是同一套页面、同一套聚光遮罩与字幕样式），再用 `ffmpeg-static` 把帧序列 + 拼接好的 PCM 音频合成 MP4。

需要注意的是，`ffmpeg-static` 的二进制在打包后位于 `app.asar` 内部，而 **asar 里的文件不能直接执行**，必须把路径替换成 `app.asar.unpacked`。

### 6. 演示页控制接口：让任何 HTML 都能被驱动

这一块是开放的。任何演示页面只要暴露两个全局对象，就能被助手驱动：

```js
// 必需：翻页（页码从 1 开始）
window.speakerDeck = {
  goTo(page) { /* 成功返回 true */ },
  next() {}, prev() {},
  current() { return 1 }, count() { return 1 }
}

// 可选：坐标聚光（相对页面的百分比）
window.speakerSpotlight = function (rect) {
  // rect = { x, y, w, h }，传 null 清除聚光
  return true
}
```

`goTo` 必须调用页面自身的翻页逻辑（保证内部页码、`.active` 类、进度条全部同步）——否则助手和页面各算各的页码，翻着翻着就错位了。

## 四、快速上手

**下载**：[⬇ 最新版本 Releases](https://github.com/zjjqy/OpenPPTSpeaker/releases/latest) —— Windows 安装包（x64），约 112 MB。

> 安装包未做代码签名，SmartScreen 会拦一下：点 **更多信息 → 仍要运行** 即可。全部构建脚本都在仓库里，你也可以自行编译。

首次启动后，到**设置**里填入 **DashScope API Key**（只保存在本机 `userData/config.json`，主进程直连云端，不经任何中转）。语音合成默认走 **Edge TTS，免费且无需 Key**——所以只填一个 Key 就能出声。

**从源码跑起来：**

```bash
git clone https://github.com/zjjqy/OpenPPTSpeaker.git
cd OpenPPTSpeaker
npm install

npm run dev          # 开发运行
npm run typecheck    # 主进程 + 渲染层类型检查
npm run package:win  # 自行打包 Windows 安装包
```

需要 Node.js >= 18。

## 五、已知限制（不藏着）

- **语音识别仅支持中文。** `paraformer-realtime-v2` 只认中文，所以英文模式下界面 / 讲稿 / 字幕都是英文，但麦克风输入（打断提问、唤醒词）仍然走中文识别。
- **CosyVoice / Sambert 是中文音色。** 只有 Edge TTS 的音色列表跟随界面语言。
- **依赖 DashScope，没有离线模式。** LLM 和语音服务都走云端。
- 目前只出了 Windows 安装包（技术栈本身跨平台，macOS / Linux 需要自行编译）。
